# Plam v2

Discord-бот для независимой системы заявок. Python 3.11, discord.py, aiosqlite.

## Установка
1. Загрузите файлы в корень репозитория GitHub, подключенного к BotHost.
2. В BotHost задайте переменную окружения `DISCORD_TOKEN` (не публикуйте токен в GitHub).
3. При необходимости задайте `GUILD_ID` для быстрой регистрации команд на одном сервере.
4. Запустите контейнер. В Dockerfile уже задана команда `python bot.py`.
5. Боту нужны права View Channel, Send Messages, Embed Links, Read Message History, Manage Roles (для выдачи ролей), а для удаления — Manage Messages. Роль бота должна стоять выше выдаваемой роли.
6. Message Content Intent не требуется для чтения личных сообщений боту; голосовые функции не используются.

## Команды
- `/form_create name review_channel admin_role approved_role` — создать форму, выбрать канал и администраторскую роль.
- `/question_add form_name text kind options` — добавить вопрос. `kind=text` — свободный ответ, `kind=choice` — фиксированные варианты, разделённые `|`.
- `/question_edit`, `/question_delete`, `/question_list` — управление вопросами.
- `/form_publish form_name channel` — панель с кнопкой подачи анкеты.
- `/form_list` — список форм.
- `/application_edit application_id answer_number new_answer` — изменить ответ в базе и опубликовать исправление.
- `/application_delete application_id` — удалить запись и основное сообщение заявки.

После нажатия кнопки бот задаёт вопросы в ЛС. Для отмены пользователь пишет `отмена`. После заполнения бот публикует в канале нумерованную заявку и все ответы отдельными сообщениями, которые остаются в истории. Администраторы принимают/отклоняют заявки кнопками.

## Ограничения и примечания
- Общего лимита на число вопросов нет, но Discord ограничивает длину отдельных команд, сообщений и частоту отправки. Длинные анкеты отправляются последовательно.
- Вариантов фиксированного вопроса — 2–25; текст ответа ограничивается лимитом одного сообщения Discord.
- Для каждой анкеты используется текущий список вопросов. Не изменяйте вопросы во время активного заполнения — это может изменить последовательность.
- Удаление заявки удаляет её основное сообщение и запись в базе, но оставляет опубликованные ответы в канале. Для полного удаления сообщений с ответами нужна отдельная функция учёта их ID.
- Для сохранности SQLite на BotHost используйте постоянное хранилище, если оно доступно. Иначе данные могут исчезнуть при пересоздании контейнера.
- Предыдущая база Nexus v0.1 имеет другую схему. v2 использует `data/plam.db` и не переносит старые заявки автоматически.
